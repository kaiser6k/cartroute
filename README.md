# CartRoute (prototype)

Golf cart / low-speed-vehicle (LSV) route planner for all 50 US states and DC. **Florida rules are verified; other states use unverified defaults.** Open `index.html` in a phone or desktop browser (works from a file; needs internet for Leaflet, OSM tiles, Overpass and Nominatim). Nothing is deployed or published.

**Not legal advice.** Rules are simplified. Local governments designate golf cart roads and can add rules. Check local ordinances and signs.

## Files
- `index.html` – the deliverable (single file, inline JS/CSS; Leaflet from unpkg CDN).
- `lib.js` – routing + legality core (pure JS; unchanged by the profile work). `profile.js` – profile/cart/storage logic (pure JS). Both are inlined into index.html by `build.sh`; `index.src.html` is the template.
- `places.js` – business search logic (queries, parsing, categories, sorting, reachability wording); inlined by `build.sh`.
- `geo.js` – geolocation helpers (US check, error messages, options); inlined by `build.sh`.
- `states.js` – GENERATED by `node tools/gen-states.js` from `tools/state-rules.json` (research, 51 entries) and `tools/us-states.geojson` (outlines): name, abbreviation, LSV road limit, verified flag, bbox, centroid, coarse outline, one source link per state. Offline state detection = point-in-outline (bbox pre-check; offshore points snap to the nearest outline within ~0.5 degrees).
- `ui-test.js` – jsdom click-through test (needs `npm i jsdom@24`; run `NODE_PATH=<dir>/node_modules node ui-test.js`).
- `test.js` – `node test.js` runs unit tests and routing tests on `fixtures/palmbay.json` and `fixtures/cocoa.json` (real Overpass extracts pulled 2026-10-10).

## Accounts, profile and setup wizard
- **First launch** (no saved profile) opens a full-screen 7-step wizard: welcome + name, cart type/make/nickname, top speed, equipment + registered/titled/insured, driving preferences (day/night, 25/30/35 mph assumed-road cutoff, strict mode, crossings), home area (Palm Bay, Cocoa Beach, or a geocoded address), and a review screen with the plain-language legal status and the LSV checklist. Nothing is saved until Finish. Reload mid-wizard restarts it.
- **Later launches** skip the wizard and open the map centered on the home area, with the active cart in a header chip (tap it or the gear for Settings).
- **Settings (gear):** edit name; add / edit / delete / switch carts (the last cart can't be deleted); change preferences and home area (saved immediately); re-run the wizard; export the profile as JSON (download + shown in a text box for copy/paste); import JSON from a file or paste (validated, migrated, confirmation before replacing); reset all data (confirmation, then the wizard restarts).
- **Storage:** no backend. The profile (name, carts, active cart, prefs, home) is stored in `localStorage` under `cartroute.profile.v1` with a `version` field; older/unversioned data is migrated, newer versions are rejected on import. If localStorage is blocked (private mode) or fails (quota), the app keeps the profile in memory and shows a visible notice with a reminder to export. Data stays on this device/browser only; it is not synced across devices.
- Settings that used to sit on the main screen now live only in the profile; the main screen shows a read-only status summary.

## Find places (business search + "can my cart get there?")
- **Panel:** collapsible "Find places" card under the map. Type a name (Photon, no bounding box (results are filtered to the US), biased toward the search center; typing is debounced 700 ms, identical queries are not re-sent) or tap a category chip: Food, Coffee, Groceries, Gas / EV charging, Golf courses, Parks / Beach access, Pharmacy, Restaurants / Bars, Shops. Chips query OpenStreetMap through Overpass (`amenity`, `shop`, `leisure`, `natural` tags; nodes, ways and relations using `center`) within 1, 3 (default) or 5 km of the map center, or of your location if you pick "Around: My location" (the browser is asked only when you search with that option).
- **Results:** nearest first (straight line), up to 40, with category emoji markers on the map. Each shows name, category, distance and a badge: "Reachable by legal route (x.x mi, ~y min)", "Needs assumed roads", "No legal route found", "Checking...", or a walk note. Tapping a result or marker shows address, phone, website, the raw `opening_hours` text (labelled as OpenStreetMap data that may be out of date; the app never says open or closed), plus **Route here** (sets the destination) and **Start from here**.
- **Reachability** reuses the unchanged router. The top 10 are checked automatically using one road download that covers your start and those places (a 5 km box limit; places that would not fit wait for a tap). The rest are computed when tapped, from the cached graph when it covers them. The measuring point is your start point if set, else your location if known, else the search center, and the panel says which. "Needs assumed roads" appears when 10% or more of the route length depends on roads with no posted speed in OSM (most untagged residential streets), so it is common; golf cart routes also always rely on unverified local designation (see the cart status).
- **Places off the legal network:** if the place is more than 150 m from a road the cart may use, the badge says how far the legal route ends ("nearest legal road is x m away; you may need to walk") instead of failing.
- **Privacy:** only the search center (or your position, if chosen) goes to Photon and Overpass as query coordinates; results are cached in memory for the session and nothing is saved.
- **Limits:** the public Overpass mirrors are flaky (private.coffee returned 500 for some of my fixture queries and had to be retried) and from `file://` only private.coffee works, so searches may fail; the panel then shows a clear message suggesting a retry or hosting on https. Categories are rough OSM tag groups, not a business directory; many places lack names, hours or phone numbers.
- Fixtures: `fixtures/places_groceries_palmbay.json` (real, 17 convenience stores/groceries within 3 km of 27.9856,-80.6262) and `fixtures/places_restaurants_cocoa.json` (real restaurants/bars within 2 km of Cocoa Beach), fetched 2026-10-10.

## Map tiles, geocoding and Overpass from `file://`
Pages opened from `file://` send no Referer. In a real browser (Brave on Windows) that gets OSM tiles a 403 "Access blocked" image and CARTO tiles an "API KEY REQUIRED" watermark, both served as valid HTTP 200 images, even though curl from a server gets normal tiles. So:
- **Default tiles are Esri** for every style: Street = World Street Map, Satellite = World Imagery, Topo = World Topo Map, Dark = Dark Gray Canvas Base + Reference (labels) overlay. Dark Gray has no tiles above zoom 16, so the map upscales from 16 there. Esri serves plain images with no Referer check.
- **Esri terms (short):** Esri's basemap services are free for light use with attribution (shown on the map); heavy or commercial use needs an ArcGIS developer account/API key and falls under Esri's Terms of Use. This prototype is low volume only. Check Esri's current terms before wider release.
- **Switch map button:** because blocked tiles are valid images, the error event can't see them. The map has a visible "Map not loading or showing a warning? Switch map" button that cycles Esri Street -> Esri Topo -> Esri Imagery -> CARTO -> OSM -> back (this session only).
- **Settings -> Driving preferences:** "Map style" (Auto / Street / Satellite / Topo / Dark) and "Map provider" (Esri default / CARTO / OpenStreetMap), saved in the profile (`prefs.basemap`, `prefs.tileProvider`). A note next to the provider list says CARTO and OSM may show "API key required" or "Access blocked" on file:// pages.
- **Automatic fallback (real errors only):** after 5 tile errors with no successful load, the map moves to the next Esri layer with a notice; it never falls back into CARTO or OSM on its own.
- **Address search:** Photon (photon.komoot.io; CORS `*`, no key, results filtered to the US) first. Nominatim returns 403 without a Referer, so it is used only as a fallback on real http(s) pages, never on `file://`. If search can't be reached the message says to tap the map. Results outside the US are rejected.
- **Overpass:** `overpass-api.de` answered 406 to browser-like requests without a Referer, so the mirror order is private.coffee, kumi.systems, overpass-api.de. Only private.coffee worked in my checks, so road data from `file://` depends on that one mirror.
- **Verified with curl (no Referer, `Origin: null`, browser UA, Palm Bay ~28.03N -80.59W):** Esri Street z13 200 image/jpeg 14 KB, z16 22 KB, z19 6.5 KB; Imagery z13 11 KB, z19 16 KB; Topo z13 13 KB, z19 5.8 KB; Dark Gray Base z13 6.6 KB, z16 9.5 KB (z17+ returns a 2.5 KB "not yet available" placeholder, hence the zoom cap); Dark Gray Reference z13 PNG 3 KB. I opened street z16 and dark z13 tiles and they showed real maps. This does not prove how Brave renders them.

## Hosting it properly (recommended)
The real fix is serving the page over https so browsers send a Referer; then CARTO and OSM tiles (and Nominatim, and overpass-api.de) generally work, and `navigator.geolocation` is allowed everywhere. Nothing is deployed by this project. Free options:
- **GitHub Pages:** put `index.html` in a repo, Settings -> Pages -> deploy from the main branch; you get `https://<user>.github.io/<repo>/`.
- **Netlify Drop:** go to app.netlify.com/drop and drag the folder containing `index.html`; you get an https URL immediately.
The project is a single file with no build step needed on the host. Remember the OSM/Nominatim usage policies (low volume, attribution) if you share the link widely.

## Use my location (geolocation)
- **Only on a tap.** Nothing calls `navigator.geolocation` at page load or in the wizard unless you press a location button.
- **Main map:** a crosshair icon button beside the start address box, which also centers the map and shows the blue position dot + accuracy circle (tooltip "Use my location as start"; sets the route start and fills the box with "My location (lat, lon)", upgraded to a Photon reverse-geocoded address when available), and a compact "Follow me" / "Stop following" button (`watchPosition` / `clearWatch`). An optional checkbox reroutes from your new position as you move (at most every 15 s, after moving 40 m or more; each reroute downloads road data again, so it uses data).
- **Home area:** "Use my current location as home area" in the wizard's home step and in Settings.
- **Settings used:** `enableHighAccuracy: true`, 15 s timeout, 10 s cached positions allowed.
- **Failures get plain-language messages with the address/tap fallback:** permission denied (how to re-enable it in Safari/Chrome site settings), position unavailable, timeout, unsupported browser, and insecure context (needs https:// or localhost; some browsers also block location on file:// pages).
- **US only:** a fix outside the US (rough boxes: contiguous US, Alaska, Hawaii; they include some water and slivers of Canada/Mexico) shows an "outside the United States" message and moves the map to your home area instead; the start is not set and Follow stops. A fix that is in the US but far from any legal road is handled by the normal routing messages. Fixes less accurate than about 1.5 km show a warning.
- **Privacy:** your position is used only in this browser (map display and routing) and is never sent anywhere by CartRoute except as map coordinates in the road-data and address lookups you trigger. It is **not saved** to the profile, storage or exports unless you tap "Use my current location as home area", which saves that one point as your home.

## How it works
1. Active cart + preferences from the profile -> `cartStatus()` gives a legal class (golf / LSV / not eligible), a plain-language explanation, and an LSV upgrade checklist.
2. Tap two points or geocode addresses (Nominatim, 1 request/s, US only). Max 5 km between points.
3. Overpass fetch of `highway` ways in the padded bounding box (mirrors: overpass-api.de, private.coffee, kumi.systems; 45 s timeout, 2 rounds of retries, in-memory cache).
4. Graph built in the browser; edges filtered per cart class; Dijkstra; route drawn, with distance/time, "assumed" segments dashed orange, crossings marked.
5. If no legal route: explains why and draws the shortest path that would need the illegal road(s) (penalized Dijkstra), marked NOT legal.

## Rules encoded and sources
Verified by reading the statutes on leg.state.fl.us / flsenate.gov on 2026-10-10.

| Rule | Source | In code |
|---|---|---|
| Golf cart = built for golf course, cannot exceed 20 mph | Fla. Stat. 320.01(22) | speed > 20 is not a golf cart |
| LSV = four-wheeled, top speed >20 and <=25 mph; must meet 49 CFR 571.500 | 320.01(41) | LSV needs 20 < speed <= 25 |
| Golf carts only on county/municipal roads **designated** by local government (and signed), or water-control-district roads | 316.212(1) | roads allowed only if tagged `golf_cart=yes/designated`, or (planning mode) assumed designated at/under a speed cutoff |
| Golf cart may cross a state highway only at FDOT-approved crossings | 316.212(2) | crossings allowed at intersection nodes only, flagged with a warning |
| Night: sunset to sunrise only if the local government allows it AND cart has headlights, brake lights, turn signals, windshield | 316.212(5) | "daytime only" unless equipped and requested; always flagged "check local authorization" |
| Required equipment: brakes, steering, tires, rearview mirror, red front+rear reflectors | 316.212(6) | cart without mirror or reflectors is blocked |
| Driver: license/learner permit if under 18; photo ID if 18+ | 316.212(7) | not enforced (mentioned only) |
| Local ordinances may be stricter; sidewalk use only by ordinance (<=15 mph) | 316.212(8) | sidewalks/footways never routed |
| LSV only on streets posted <=35 mph; may cross faster roads at intersections | 316.2122(1)(a) | LSV speed cap 35; crossing at shared nodes |
| LSV equipment: headlamps, stop lamps, turn signals, taillamps, reflex reflectors, parking brake, mirrors, windshield, seat belts, VIN; titled/registered/insured; driver license | 316.2122(1)(b)-(d) | LSV checklist |
| Counties/cities (and FDOT) may prohibit LSVs on roads | 316.2122(3),(4) | not in map data; warning only |
| Never motorways/trunk/limited-access, never sidewalks | statute silent on golf carts for these (not designated); trunk excluded by project spec | motorway, motorway_link, trunk, trunk_link, footway, steps, pedestrian never used; no pass-through of limited-access nodes |

Default speeds when `maxspeed` is missing (flagged "assumed"): residential 25, living_street 15, service 15, unclassified 30, tertiary 35, secondary/primary 45. Bare `maxspeed` numbers are read as mph (Florida convention in practice; OSM's formal default is km/h).

## Things I am NOT sure about / assumptions (please verify)
- **There is no 25 mph or 30 mph number for golf carts in the statute.** 316.212 only says "designated" roads. The 25 mph cutoff (selectable 25/30/35) is my assumption of typical local practice; the app labels those roads "assumed". Strict mode uses only OSM `golf_cart=yes`, which is rare.
- Whether golf carts may cross a *non-state* higher-speed road at an intersection is not clearly stated (316.212(2) covers state highways with FDOT approval). The app allows crossings at intersections (option) and warns.
- 20 mph cart with full LSV equipment: statute defines an LSV as faster than 20 mph, so such a cart may legally still be a golf cart. App warns and uses golf rules. Confirm with FLHSMV.
- LSV night/daytime: 316.2122 states no daylight restriction; not independently confirmed against other statutes (e.g. general lighting rules in ch. 316).
- Trunk roads (e.g. US-1 where posted <=35) are excluded entirely, and trunk crossings are allowed except `expressway=yes`. This is a conservative project choice, not statute text.
- Sources checked: leg.state.fl.us 316.212, 316.2122; flsenate.gov 320.01. FLHSMV site was not separately consulted.

## Known limitations / next steps
- Golf cart legality is mostly "assumed": needs real designated-road data per county/city (Brevard County, Palm Bay, Cocoa Beach, etc.) - e.g. ordinance GIS layers - ahead of any speed heuristic.
- Many neighborhoods are islands bounded by 35+ mph roads; in tests only ~4-5 of 25 random golf cart pairs were routable. Crossings need the cross street mapped through the intersection (shared node); offsets are not bridged, median links only for dual carriageways of the same road within 60 m.
- No turn-by-turn directions, sunset/sunrise calculation, one-way exceptions, bridges/causeway restrictions, or `*:conditional` tags.
- Estimated time ignores stops/traffic; adds 20 s per crossing.
- Overpass public servers are rate-limited: consider a small backend with caching, and a self-hosted/tiled road extract. Nominatim policy: a backend should set a User-Agent.
- Add a native/PWA wrapper, saved carts, report-a-road feedback ("this road is/isn't golf cart legal"), and a per-city rules table.
- Build: `./build.sh` (inlines `lib.js` into `index.html`).

## Address autocomplete (type-ahead)

The start field, destination field, the setup wizard's home-area field and the Find places text box show suggestions as you type.

- After 3 characters and a ~300 ms pause, the app asks Photon (photon.komoot.io, `limit=6&lang=en`, no bounding box, results filtered to the US, biased toward your position or the map center). Stale requests are cancelled (AbortController).
- Each row shows a type icon, a primary line (name, or house number + street) and a secondary line (city, county, state). States: "Searching…", "No places found", and an error row that points you to the tap-the-map fallback.
- Focusing an empty field shows your last 5 picks (saved in the profile on this device, included in profile export) with a "Clear recent searches" row; the start field also offers "My location" first (location is only requested when you tap it). The setup wizard does not save recents.
- Picking a row fills the full label, drops the marker, sets the start/destination and recenters the map. Enter picks the highlighted row, otherwise runs the existing Find button. Arrow keys, Escape, ARIA combobox/listbox, 48 px rows, dark-mode styles, closes on outside tap or blur.
- Privacy: the text you type and the map center (or your position) are sent to Photon (komoot) to get suggestions. Nothing else is sent; only the last 5 picks are stored locally.
- Logic lives in `autocomplete.js` (inlined by `build.sh`); fixtures in `fixtures/photon_*.json` are real Photon responses.

## Vehicle types and Europe mode

**Vehicle types** (`vehicles.js`, one data table used in the US and in Europe): Golf cart and Street-legal LSV (existing Florida logic, unchanged), plus Moped / scooter (50cc, up to ~30 mph; EU AM class), Motorcycle (full road legal), Electric scooter / e-bike, and Light quadricycle (EU L6e, 45 km/h). Each row lists the OSM road classes it may drive, its road speed cap, whether it may use motorways/freeways and whether it may use cycleways/designated paths. `GC.classifyWay` / `GC.planRoute` apply the table when `rules.cls === 'veh'`; golf/LSV rules are untouched.

| Type | Motorway / freeway | Trunk / expressway | Cycleway / path | Road speed cap (US / EU) |
|---|---|---|---|---|
| Moped | no | no | no | 73 km/h (45 mph) / 80 km/h |
| Motorcycle | yes | yes | no | none |
| E-scooter / e-bike | no | no | yes (bicycle=designated/yes) | 57 km/h (35 mph) / 50 km/h |
| L6e quadricycle | no | no | no | 80 km/h |

Vehicle routes are weighted by travel time (road speed up to your top speed), so a motorcycle prefers a freeway when it is faster. These are general vehicle-class assumptions, not verified state or national law; the US state warning still shows for unverified states.

**Europe** (`europe.js`, generated by `node tools/gen-europe.js` from Natural Earth 50m outlines in `tools/europe-countries.geojson`): EU-27, UK, Norway and Switzerland are detected from the start point (or map center) by country outline. Europe shows one compact warning, "Rules in [Country] aren't verified. Golf carts are generally not road-legal in the EU; check local law.", with a link to EU rules (EUR-Lex) and to the country's authority (a research-sourced link where there is one, otherwise a web search). Units follow the region (km/h and km; UK stays in mph/miles), with a Settings override (Automatic / km/h / mph). Speeds are stored in mph internally. OSM `maxspeed` is read as km/h in Europe and mph in the US unless the tag names a unit. Golf cart / LSV types are reported as not road-legal in Europe, with a one-tap switch to an L6e quadricycle.

Address search no longer filters to the US (Photon uses a lat/lon bias; Nominatim has no country filter). The supported area is the US plus Europe (`GEO.supported`); elsewhere shows an out-of-region message. The 12 km route limit is unchanged. The LSV callout is US only.

## Source layout and build (added Oct 2026)

`index.html` is the **build output** that Cloudflare Pages serves at the site root (no build command is configured; Pages just serves the files).
Edit the sources, then run `sh build.sh`, which inlines `states.js, europe.js, vehicles.js, lib.js, profile.js, geo.js, places.js, autocomplete.js` into `index.src.html` to produce `index.html`. `node test.js` runs the whole test suite (also runs `test-vehicles.js` and the fixtures in `fixtures/`).
`tools/` holds the data generators and research (`state-rules.json`, `eu-rules.json`, GeoJSON borders). `research/` has the original 50-state and EU research JSON and summaries. All rules other than Florida are unverified defaults.

### Routing robustness
* The map area starts at 700 m padding around the trip and widens automatically to 2 km, then 5 km when no route is found (capped at 450 km2).
* Start and end snap to the nearest **allowed** road for the active vehicle; if that fails, to the main strongly connected network (avoids one-way stubs and islands). If the start or end sits on a road the vehicle cannot use, the app says so and states the snap distance.
* Ramp end-nodes no longer cut surface roads for vehicles that may not use freeways.
